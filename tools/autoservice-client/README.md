# AutoServiceClient — عميل Binder خام لخدمة `autoservice`

أداة جافا صغيرة (ليست JNI حرفياً — جافا عام يستخدم `android.os.Parcel`/`IBinder` العامة فقط، بلا أي كلاس من BYD) تتواصل مباشرة مع خدمة `autoservice` الأصلية عبر Binder، بالضبط بالطريقة التي أكدنا نجاحها حياً بالقسم 8.12 من `byd-seal05-research-plan.md`، لكن بقدرة أداة `adb shell service call` لا تملكها: **تمرير معامل `StrongBinder` حقيقي** (`new Binder()`) — وهذا مطلوب لكل أكواد الكتابة المرشّحة بجدول القسم 8.11.

## لماذا جافا وليس JNI/native فعلي؟

نفس المبدأ الذي أثبتناه الليلة الماضية (`ReadTest.java`): كلاسات `android.os.Parcel`، `android.os.IBinder`، `android.os.Binder` هي **كلاسات SDK عامة بأندرويد نفسه** (ليست مخفية ولا خاصة بـ BYD)، وتعمل بشكل طبيعي من أي عملية جافا تعمل تحت `app_process`. لا حاجة لـ NDK، لا حاجة لتصريف C++، لا حاجة لأي reflection على كود BYD. الاستثناء الوحيد: دالة `android.os.ServiceManager.getService(String)` نفسها مخفية (`@hide`) فبنصل لها بـreflection بسيطة — تماماً كما فعلنا مع `ActivityThread` بالجلسة السابقة.

## البناء والتشغيل

```bash
./build.sh              # يبني out/classes.dex (محلي، بلا سيارة)
./run.sh 5 i32:1001 i32:947912728   # مثال: قراءة نسبة فتح نافذة السائق (مؤكدة)
```

`run.sh` يدفع الـdex لـ`/data/local/tmp`، يشغّله بـ`app_process` بصلاحية `shell`، ثم يحذفه فوراً.

## صيغة المعطيات

- `i32:<رقم>` — يكتب عدد صحيح 32-بت بالـ Parcel.
- `binder` — يكتب كائن `android.os.Binder()` جديد (فاضي، بلا تنفيذ) كـ`StrongBinder`.

## مرجع الأكواد (القسم 8.11/8.13 من خطة البحث)

| الكود | الحالة | الشكل |
|---|---|---|
| **5** | ✅ مؤكد حياً = `getInt(device,fid)` | `i32:<device> i32:<fid>` → يرجع `[status, value]` |
| 7 | مرشّح get (قيمة عشرية) | نفس شكل 5، يرجع `[status, float]` |
| 13 | غير محسوم | نفس شكل 5، يرجع `[status, uint32]` |
| 6, 10 | مرشّح **كتابة محتملة** | `i32:<device> i32:<fid> i32:<value> binder` → يرجع `[status]` |
| 15 | مرشّح كتابة محتملة | `i32:<?> i32:<?> binder` → يرجع `[status]` |
| 16, 20 | مرشّح كتابة محتملة | `i32:<device> i32:<fid> i32:<value> binder` → يرجع `[status]` |
| 17 | ✅ مؤكد حياً = قراءة بلا معطيات | (بلا معطيات) → يرجع رقمين |

**لا أحد من أكواد الكتابة (6, 10, 15, 16, 20) مُختبَر حياً بعد.** الأداة نفسها بتطبع تحذيراً تلقائياً لو مررت 3 معطيات int32 أو أكتر (شكل كتابة محتمل)، بس هذا تذكير فقط — **القرار والمراجعة تبقى على الإنسان قبل أي تشغيل**.

## قواعد أمان صارمة لأي استخدام مستقبلي (من `CLAUDE.md`)

1. **السيارة بوضع P (متوقفة بالكامل)** قبل أي تجربة كتابة.
2. **قراءة تأكيدية** (كود 5 بنفس device/fid) قبل وبعد أي تجربة كتابة، لمقارنة فعلية.
3. **ابدأ بخاصية بسيطة وقابلة للعكس فوراً** (مثل نسبة نافذة معروفة، لا قفل أبواب ولا فرامل ولا أي شي متعلق بالقيادة/ADAS/البطارية عالية الجهد — تلك ممنوعة بالكامل دائماً).
4. **لا تخمين لقيمة الكتابة** — إذا الخاصية نسبة 0-100، لا تجرب قيمة خارج هذا المدى.
5. كل أمر جديد يُشرح للمستخدم ويُنتظر تأكيده الصريح قبل التنفيذ — بلا استثناء.
